# 말결 — AI 프롬프트 최적화 1.13.1

**내 뜻을 살리는 프롬프트.** 기존 Prompt Optimizer의 새 이름은 **말결(Malgyeol)**입니다. 기존 확장 항목을 업데이트하면 API 키와 설정을 그대로 사용합니다.

새 홍보 자료는 [말결 1.13.1 브랜드 자료](marketing/malgyeol-1.13.1/README.md)에 있습니다. `python tools/package-brand-release.py`로 스토어 업로드용 ZIP과 이미지·문구 묶음을 함께 만듭니다.

자연어 요청을 Gemini API로 분석하고, OpenAI·Anthropic·Google 및 기타 제공사의 세부 모델에 맞는 프롬프트로 재작성하는 Chrome 확장 프로그램입니다. 최적화 엔진은 Gemini로 고정되어 있으며 자동 실행 모델 전환은 없습니다. 기타 제공사의 목록은 OpenRouter에서 수집하며 확장 사용자의 요청을 OpenRouter로 중계하지 않습니다.

팝업의 **사용 설명서 ↗**를 누르면 빠른 시작과 상황별 해결 방법을 별도 탭에서 언제든 확인할 수 있습니다.

팝업의 **오류 진단 ↗**에서는 최근 7일간 최대 30개의 오류를 확인하고, API 키·프롬프트·결과·페이지 주소를 제외한 JSON 진단 보고서를 복사하거나 저장할 수 있습니다. 사용자는 보고서를 **dominicjjung@gmail.com**으로 보내면 됩니다. 다른 사용자에게 받은 보고서는 같은 화면의 **받은 보고서 열기**에서 확인합니다. 보고서는 자동 전송되지 않습니다.

API 설정 또는 사용 설명서의 **성능 평가 ↗**에서는 고정된 시험 요청 8개로 실제 Gemini 최적화를 실행하고 완료율, 핵심 정보 보존율, 의도·언어 정확도, 응답시간과 API 토큰을 측정합니다. 평가 1회는 Gemini 생성 요청 8회를 사용하며 결과는 자동 저장·전송되지 않습니다. JSON으로 저장해 버전이나 모델별 결과를 비교할 수 있습니다.

## 설치

1. Chrome에서 `chrome://extensions`를 엽니다.
2. 오른쪽 위 **개발자 모드**를 켭니다.
3. **압축해제된 확장 프로그램을 로드합니다**를 누릅니다.
4. 이 `prompt-optimizer` 폴더를 선택합니다.

코드를 수정한 뒤에는 확장 프로그램 카드의 새로고침 버튼을 누르고 열려 있던 AI 페이지도 새로고침하세요.

## Gemini API 키 등록

1. 확장 프로그램 아이콘을 누르고 **Gemini API 설정 ↗**을 엽니다.
2. [Google AI Studio](https://aistudio.google.com/apikey)에서 발급한 키를 붙여넣습니다.
3. 필요하면 **이 브라우저에 키를 저장**을 선택합니다. 선택하지 않으면 브라우저 세션 동안만 보관됩니다.
4. **키 등록 / 변경**을 누르고 Chrome의 Gemini API 연결 권한 요청을 허용합니다.
5. **사용 가능한 모델 조회**를 눌러 이 키에서 `generateContent`를 지원하는 모델을 확인합니다.
6. 사용할 모델을 고른 뒤 **선택한 모델 저장**을 누릅니다.

1.10.2부터 모델 저장은 백그라운드에서 처리하고 저장된 모델을 다시 읽어 확인합니다. 현재 모델도 다시 저장할 수 있습니다. 다른 모델이 보이는데 저장되지 않으면 표시되는 구체적인 오류를 확인하세요. 확장을 업데이트한 뒤 열어둔 API 설정 탭은 닫고 팝업에서 새로 열어야 합니다.

기본 모델은 `gemini-3.5-flash-lite`입니다. 모델 목록에 기본 모델이 없으면 목록에 실제로 표시된 Flash 또는 Flash-Lite 모델을 선택해 저장하세요. 목록 조회는 생성 요청을 보내지 않으며, 목록에 보이는 모델도 프로젝트 등급과 남은 할당량에 따라 생성 요청이 거절될 수 있습니다.

Gemini API의 무료 등급과 호출·토큰 한도는 Google 정책과 프로젝트 상태에 따라 달라집니다. 확장 프로그램은 유료 등급으로 자동 전환하거나 결제를 활성화하지 않습니다. 자세한 내용은 [Gemini API 요금 안내](https://ai.google.dev/gemini-api/docs/pricing)에서 확인하세요.

## 사용법

1. 팝업에 평소처럼 요청을 작성하거나 지원 AI 페이지에서 **페이지에서 가져오기**를 누릅니다.
2. 최종 프롬프트를 사용할 **대상 AI → 대상 세부 모델**, 응답 언어, 최적화 모드를 선택합니다. 해당 브랜드의 모델만 표시되고 선택값은 브랜드별로 기억됩니다.
3. 위쪽 상태 카드에서 **API 사용 준비 · 키 등록됨**과 서버 접근 허용 표시를 확인하고 **Optimize · Gemini API**를 누릅니다.
4. 결과를 확인하고 **Copy** 또는 **Replace**를 사용합니다.

Replace는 입력창 내용만 교체하며 메시지를 자동 전송하지 않습니다. 입력창이 바뀐 경우 오래된 결과로 덮어쓰지 않습니다. **원문 복구**로 직전 교체를 되돌릴 수 있습니다.

### 대상 세부 모델과 적용 지침

**대상 세부 모델**은 완성된 프롬프트를 사용할 모델입니다. API 설정에서 고른 **Gemini 최적화 엔진 모델**과 독립적이며, 대상 모델을 바꿔도 API 실행 모델이나 키가 변경되지 않습니다. 웹 AI의 모델을 자동 감지하거나 변경하지 않으므로 웹 페이지에서 선택한 모델에 맞춰 직접 고르세요. 잘 모르면 **모델 모름 / 브랜드 공통**을 사용하세요.

공식 문서에서 확인한 GPT-4.1의 명시적 지시, OpenAI 추론 계열의 목표·제약 중심 지시, Gemini의 문맥 배치, Claude의 자료 구분과 버전별 완료·검증 지침을 실제 Gemini 재작성 요청에 적용합니다. Default·ECO·Precision·Natural·Custom과 함께 적용되며 원문의 명시적 조건을 우선합니다. 선택 아래의 **적용 지침과 공식 출처**에서 확인할 수 있습니다.

주요 텍스트 모델의 API 메타데이터와 문서 기반 지침을 사용하며 계정별 사용 가능 목록을 보장하지 않습니다. 문서상 차이가 확인되지 않은 세부 버전은 계열 지침을 공유합니다. 웹 입력창에 붙여넣는 텍스트만 생성하므로 시스템 역할, JSON Mode, 도구, 추론 예산을 설정하지 않습니다. 기존 규칙의 출처는 [초기 모델별 지침](docs/MODEL_PROFILES.md), 현재 자동 갱신·검증·운영 방법은 [동적 Registry 안내](docs/DYNAMIC_REGISTRY.md)에 정리했습니다.

### 모델 자동 갱신과 검색

대상 AI를 고르고 **모델명 검색**으로 해당 제공사의 모델을 찾을 수 있습니다. **모델 목록 갱신**은 생성 요청 없이 공개 Registry를 확인합니다. 시작 시 번들/마지막 정상 캐시를 사용하고, 하루가 지나면 새 데이터를 확인합니다. 실패하거나 손상된 JSON이면 기존 목록과 프로필을 유지합니다. NEW는 최근 14일 안에 Registry가 처음 발견했다는 뜻이며 공개 출시일이나 무료 사용을 보장하지 않습니다.

프로필은 기본·상속(`fallback`), 비활성 후보(`candidate`), 고정 샘플 실제 평가 통과(`validated`), 종료(`deprecated`) 상태로 관리합니다. 후보는 검증 전에는 적용하지 않습니다. 선택 모델이 목록에서 사라져도 설정 ID를 지우지 않고 공통 지침을 사용합니다.

GitHub Actions는 매일 공식 목록 API와 공개 OpenRouter 목록을 확인합니다. 운영자의 후보 생성·실제 평가는 **별도 Secrets와 비용·호출 한도**를 설정해야 활성화되며 기본값은 0입니다. 사용자 개인 키를 운영 자동화에 사용하지 않습니다. 설정 화면의 ‘성능 평가’는 별개의 사용자 수동 실행 기능입니다.

입력창 연결이 끊겼다면 팝업 아래의 **↻ 다시 찾기**를 누르세요. 현재 페이지의 입력창 후보를 처음부터 다시 확인합니다. 계속 찾지 못하면 표시되는 **페이지 새로고침**을 눌러 페이지가 열린 뒤 확장 프로그램을 다시 여세요. 페이지 새로고침 시 전송하지 않은 페이지 입력 내용은 사라질 수 있습니다.

입력 한도는 12,000자입니다. 동시 API 호출은 한 번만 허용하며 자동 재시도하지 않습니다.

1.10.1부터 스트리밍으로 Gemini 응답을 받습니다. 서버의 최초 연결 응답은 25초, 요청 전체는 최대 90초까지 기다립니다. 결과는 정상 종료된 완성본만 표시·적용하며 중간 조각은 적용하지 않습니다. 기다리는 동안 경과 시간을 표시합니다. 시간 초과 오류에는 모델명과 연결 지연(`CLIENT_CONNECTION_TIMEOUT`)·생성 지연(`CLIENT_RESPONSE_TIMEOUT`)을 구분해 표시합니다. 후자는 HTTP 상태 코드가 아니라 확장 프로그램의 대기 제한입니다.

API 상태 카드는 키 미등록, 서버 접근 권한 없음, 사용 준비, 요청 중, 마지막 API 응답 성공·실패를 구분합니다. **↻ 상태 확인**은 저장된 키 유무와 Chrome 권한만 확인하며 Gemini 생성 요청을 보내지 않습니다. 사용 준비는 인증·할당량 확인과 별개이며 실제 최적화 요청이 성공하면 **Gemini API 응답 확인됨**이 표시됩니다. 키나 권한이 준비되지 않았다면 Optimize가 비활성화됩니다. 페이지 미니 도구에서도 API 준비 상태를 확인할 수 있습니다.

### 최적화 모드

- **Default:** 명확하고 균형 있게 재작성
- **ECO:** 의미 있는 조건은 유지하면서 짧게 재작성
- **Precision:** 목표·조건·검증 기준을 구체화
- **Natural:** 자연스럽고 덜 형식적인 문체로 재작성
- **Custom:** 자동 콘셉트 조합 또는 수동 최적화 지침 사용

### Custom 모드

**Custom**을 선택하면 두 가지 설정 방식이 표시됩니다. 두 방식 모두 등록한 개인 Gemini API 키를 사용합니다.

- **자동 · 콘셉트 조합:** 정확함, 절약, 자연스러움, 전문성, 친근함, 명료함, 구조화, 창의성, 상세함, 실용성 중 하나 이상을 체크합니다. 예를 들어 정확함·절약·친근함을 동시에 선택할 수 있습니다. 원문의 조건과 사실을 우선하며, 절약과 상세함을 함께 선택하면 불필요한 반복을 줄이고 필요한 세부 설명을 유지하도록 지시합니다. 절약은 프롬프트 길이를 줄이는 방향이며 API 토큰이나 요금 절감을 보장하지 않습니다.
- **수동 · 직접 지침:** Gemini가 원문을 어떻게 재작성할지 최대 6,000자로 직접 입력합니다. 예: “목적과 필수 조건을 정리하고, 정중하고 친근한 말투의 짧은 프롬프트로 재작성해 줘. 최종 프롬프트만 반환해 줘.” 이 지침은 재작성 방식이고 **나의 요청**은 재작성할 원문입니다.

Custom 설정과 수동 지침은 이 브라우저의 로컬 확장 저장소에 자동 저장됩니다. 다른 모드로 바꿔도 유지되며 Custom에서만 Gemini로 전송됩니다. 수동 지침을 삭제하려면 지침 입력칸을 비우세요. Custom 설정을 바꾸면 이전 결과가 초기화되며 다시 최적화해야 합니다. 페이지 미니 도구도 팝업에 저장된 Custom 설정을 사용합니다.

## 페이지 미니 도구

ChatGPT, Claude, Gemini 입력창 근처에 작은 Optimize 도구가 표시됩니다. 현재 사이트 브랜드에 저장된 세부 모델 지침을 사용합니다.

- `⠿` 손잡이를 끌어 원하는 위치로 옮길 수 있습니다. 위치는 사이트별로 저장됩니다.
- `−`를 누르면 작은 `✦` 아이콘으로 최소화됩니다. 아이콘을 클릭하면 펼쳐지고, 아이콘 자체도 끌어서 이동할 수 있습니다. 최소화 상태는 브라우저에 저장됩니다.
- 팝업의 **미니 도구 아이콘 펼치기**로도 복원할 수 있습니다. 최소화·이동·복원은 API를 호출하지 않습니다.
- `×`를 누르면 도구를 숨깁니다.
- 다시 표시하려면 확장 팝업에서 **페이지 미니 도구**를 켭니다.

ChatGPT 사이트 지원은 최종 프롬프트를 입력창에 넣기 위한 기능입니다. OpenAI API를 호출하거나 OpenAI API 키를 사용하지 않습니다.

## 데이터와 권한

- 최적화 시 원문과 선택 설정을 `generativelanguage.googleapis.com`의 Gemini API로 전송합니다.
- API 키는 요청 헤더에만 사용합니다. 기본 저장 위치는 `chrome.storage.session`입니다.
- 영구 저장을 선택하면 현재 Chrome 프로필의 `chrome.storage.local`에 저장됩니다. 별도 암호화 금고는 아닙니다.
- 키와 초안은 Chrome 동기화 저장소를 사용하지 않습니다.
- 요청과 결과 초안은 브라우저 세션 동안만 보관하며 Reset으로 즉시 지울 수 있습니다.
- 재사용하는 Custom 수동 지침과 콘셉트 설정은 로컬 저장소에 보관합니다. 수동 지침은 AI 웹사이트 및 오류 진단 보고서에 노출하지 않습니다.
- 확장 프로그램의 프롬프트 생성 요청은 Gemini API만 사용합니다.
- 공개 모델 Registry를 받기 위해 `hion89.github.io/Prompt-helper/registry/`에 읽기 전용 GET 요청을 보냅니다. 이 요청에는 프롬프트·Custom 지침·API 키를 넣지 않으며 쿠키와 referrer도 보내지 않습니다. GitHub 호스트 연결 권한은 이 JSON 동기화에 사용합니다.

## 오류 확인

- `HTTP 404 / NOT_FOUND`: 저장한 모델이 현재 키에서 지원되는지 모델 목록을 다시 조회하세요.
- `HTTP 429 / RESOURCE_EXHAUSTED`: Google AI Studio에서 프로젝트의 분당·일일 호출 및 토큰 할당량을 확인하세요.
- 인증 오류: 키를 삭제한 뒤 올바른 Gemini API 키를 다시 등록하세요.
- 연결 오류: 확장 프로그램을 다시 로드하고 Gemini API 권한이 허용됐는지 확인하세요.

확장 프로그램은 실패 시 다른 모델로 자동 전환하거나 같은 요청을 자동 재시도하지 않습니다.

## 개발 및 검증

별도 빌드 과정은 없습니다. Node.js 22 이상에서 실행합니다.

```bash
npm test
npm run validate
npm run test:browser
```

스토어 업로드용 ZIP은 Python 3.9 이상에서 `python tools/package-store.py`로 생성합니다. 결과는 Git에서 제외되는 `store-submission/upload/malgyeol-{버전}.zip`에 저장됩니다. ZIP 최상위에 `manifest.json`이 들어가며 실행 파일만 포함합니다. 테스트·브라우저 프로필·홍보 자료·개인 파일은 포함하지 않습니다. 업로드 파일 목록과 SHA-256은 같은 제출 폴더에 기록됩니다.

- `background/`: Gemini 호출, 키 저장, 메시지 검증
- `providers/remote-optimizer.js`: 재작성 요청 생성, Gemini 응답·오류 검증, 모델 목록 조회
- `content/`: 지원 사이트 입력창 연결과 이동 가능한 미니 도구
- `popup/`, `options/`: 팝업과 Gemini API 설정 화면
- `shared/`: 설정 정규화 및 저장

내부 규칙 기반 컴파일러 코드는 테스트 도구에서 프롬프트 구조 검증에 사용되지만 사용자 실행 경로에서는 사용되지 않습니다.
